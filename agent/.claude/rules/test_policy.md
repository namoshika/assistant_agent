# テスト規約

## 資材概要
以下のテストを管理している。

- **単体テスト** (`tests/unit/`)
- **統合テスト** (`tests/integration/`)
- **テストデータ** (`tests/data`)

## 実行方法
コード生成時にテストも生成し、実行する。

```sh
# 単体テストを実行
uv run pytest tests/ -m 'not integration' -v

# 結合テストを実行 (AIはチェックのみ行う。実際の実行は人が行う)
uv run pytest tests/ -m 'integration' -v --collect-only
```

## 方針 (全テスト共通)

- クラスが外部に対して持つ機能を対象に行う (内部のメソッド (`_` から始まるメソッド) やロジックに対するテストは行わない)
- 対象クラスはモック化しない (参照する外部のインスタンスやクラスをモック化する)

## 方針 (結合テストのみ)

- 実際の外部システムに接続し、エンドツーエンドの動作を確認する (モック使用を最小限にする)
- `@pytest.mark.integration` デコレータを各テスト関数に付与する

## テストの書き方
全体的な方針は以下の通り。

- テスト用コードは簡潔な記述をすること
  - クラス: テスト対象が一つの場合はモジュールにテストメソッドを直接定義 (テストクラスを作成しない。逆に複数の場合は作成する)
  - メソッド: インデントレベルを低く抑える。"試験準備"～"結果検証" の各セクションを "#～" で区切る
- モックには `MockerFixture`, `unittest.mock.MagicMock` を使用

各要素は以下のルールに沿うこと。

- **テストモジュール**:
  - **注意:** コメント, docstring を書かない (ヘルパー・フィクスチャ・テストメソッド以外の内部関数を含む)
- **テストクラス:** テスト対象クラス単位で `Test{TargetClassName}` の命名で作成する
- **テストメソッド**: テスト対象メソッド単位で `test_{target_method_name}_{連番:02}` の命名で作成する。
  - **注意:** 連番は少なく抑え、必要な場合 (検証するインスタンスが異なるなど) のみ追加する。
  - **注意:** テスト対象が環境変数を要し、その値が未設定時は試験実施前に `pytest.fail()` でテスト失敗にする
  - **注意:** 同一フィクスチャインスタンスで複数シナリオを検証できる場合は1つのテストメソッドに統合する
  - **注意:** モックのリセット (`reset_mock()` 等) を要する場合は別のテストメソッドに分割する
  - **注意:** 複数シナリオを1メソッドに統合する場合の観点区切りは `# 観点N: 説明` の形式のみ (装飾文字 `-` 等を加えない)
- **フィクスチャ**: 複数テストで試験対象が共通の場合は fixture 化する
  - **注意:** 単一ファイル内で使用の場合: 各テストファイルに定義
  - **注意:** 複数ファイルで共通の場合: `conftest.py` に定義

例 (テスト対象モジュール内にクラスが一つの場合):

```python
@pytest.fixture(scope="...")
def fixture_name():
    """フィクスチャが生成するものを説明

    テスト用フィクスチャが有ればテストメソッド群の上に定義。
    """
    ...

@pytest.mark.integration # (結合試験の場合はマークを付与。単体テストの場合は不要)
def test_some_method_01(mocker: MockerFixture):
    """some_method_01 に対しテストすること

    観点1: 各仕様を満たすこと
    観点2: ...
    """
    # 試験準備
    ...

    # 試験実施
    ...

    # 結果検証
    # 観点1 (各検証と対応する観点番号を記載)
    assert ...
    # 観点2: docstring とコメントが 25 行以上離れている場合は観点内容を引用する
    assert ...

def _helper_method(connected: bool = False):
    """ヘルパーの役割を説明
    
    テスト用インスタンス生成ヘルパーが有ればテストメソッド群の後ろに定義。
    """
    ...
```

例 (テスト対象モジュール内にクラスが複数の場合):

```python
class TestSomeClassA:
    def test_some_method_01(self):
        """SomeClass.some_method_01 に対しテストすること

        観点1: ...
        """
        ...

    @staticmethod
    def _helper_method():
        """ヘルパーの役割を説明
        
        テストクラス内の場合は `@staticmethod` として定義する
        """
        ...
```
